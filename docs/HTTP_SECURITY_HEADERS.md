# HTTP security headers

LeadFlow applies one CSP system: `proxy.ts` creates a fresh nonce and CSP for
each dynamic request. `next.config.ts` applies the remaining static headers.
Keeping the CSP out of `next.config.ts` prevents browsers from intersecting two
different policies and unexpectedly blocking Clerk or Next.js.

## Headers

| Header | Policy | Purpose |
| --- | --- | --- |
| `Content-Security-Policy` | Per-request policy described below | Restricts scripts, connections, frames, images, and other browser resources. |
| `X-Content-Type-Options` | `nosniff` | Prevents MIME-type sniffing. |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Keeps full paths on same-origin navigation while limiting cross-origin referrers to the origin. |
| `Permissions-Policy` | Disables camera, microphone, geolocation, payment, USB, display capture, autoplay, motion sensors, and browsing topics | Denies browser capabilities the CRM does not use. |
| `Cross-Origin-Opener-Policy` | `same-origin-allow-popups` | Provides opener isolation while retaining compatibility with authentication popups. |
| `Cross-Origin-Resource-Policy` | `same-origin` | Prevents other origins from loading application resources. |
| `Strict-Transport-Security` | `max-age=31536000`, production only | Pins HTTPS for one year after a secure production visit. |

Framing is controlled by CSP `frame-ancestors 'none'`. `X-Frame-Options` is
intentionally omitted because it would duplicate the modern CSP control. HSTS
does not include `includeSubDomains` or `preload`: the repository does not own
or enforce HTTPS for every possible deployment subdomain, so making that
commitment here would be unsafe.

## Content Security Policy

Scripts use a per-request cryptographic nonce and `'strict-dynamic'`. The nonce
is forwarded to Next.js through request headers and explicitly passed to the
Clerk provider. Production does not allow
`'unsafe-inline'`, `'unsafe-eval'`, or wildcard script sources.

The source list is intentionally small:

- `'self'` covers Next.js assets, local fonts generated by `next/font`, local
  images, manifests, media, and same-origin API requests.
- The exact Clerk Frontend API origin is derived from the public Clerk
  publishable key. Client-supplied hosts are never used.
- `https://challenges.cloudflare.com` supports Clerk bot challenges.
- `https://*.protect.clerk.com` supports Clerk protection scripts, frames, and
  connections.
- `https://clerk-telemetry.com` and
  `https://*.clerk-telemetry.com` support Clerk telemetry connections.
- `https://img.clerk.com` supports Clerk account and user images.
- `data:` and `blob:` are limited to image loading; `blob:` is also allowed for
  workers. They are not script sources.

There are no browser-side analytics or monitoring providers in the current
application. Arcjet, PostgreSQL, and Resend are server-side integrations and do
not need CSP access. Add their browser origins only if a future client-side SDK
actually makes requests to them.

`style-src 'unsafe-inline'` is the only production inline exception. Clerk's
prebuilt components and React style props currently emit inline styles. This
does not permit inline scripts and should be removed if those components gain
nonce or external-stylesheet support.

The application cannot be embedded because `frame-ancestors 'none'` applies to
every proxied document. `object-src 'none'`, `base-uri 'self'`,
`script-src-attr 'none'`, and `form-action 'self'` further reduce injection and
navigation risk.

## Development differences

Development adds `'unsafe-eval'` for Next.js source maps and hot reloading, plus
`ws:` and `wss:` in `connect-src` for the development WebSocket. Production
removes all three exceptions and adds `upgrade-insecure-requests`. HSTS is
absent during local development so HTTP localhost remains usable.

## Adding a provider

Before changing the policy, identify every browser resource type the provider
loads in a production browser session. Add only exact HTTPS origins to the
corresponding directive in `lib/security-headers.ts`; do not add a scheme-wide
source or `*`. Keep server-only providers out of CSP. Then add a focused unit
assertion, exercise the integration in Playwright, inspect the browser console
for CSP violations, and run the production build. If the provider requires
inline script or evaluation, prefer a nonce-compatible integration and record
any unavoidable exception here with a removal condition.

## Verification

`lib/security-headers.test.ts` verifies production and development policy
construction, nonce generation, exact Clerk origin extraction, HSTS behavior,
frame denial, and the absence of wildcard/unsafe production script sources.
`e2e/security-headers.spec.ts` checks representative page, Clerk, demo, and API
routes; confirms local HSTS absence; loads a static asset and same-origin API;
captures browser CSP errors; and completes the demo authentication redirect.
